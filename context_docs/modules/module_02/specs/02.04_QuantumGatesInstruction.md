This section continues Module 02 — Quantum Computing Fundamentals. 02.03 gave a state a picture and ended by asking how to move a state from one point to another. This page answers it.
________________________________________
Goal
Teach the learner how a gate moves a state, building on 02.03's picture of a state as a point on a sphere.
The central progression is:
A GATE → A MOVE OF THE POINT → HEIGHT SETS THE PROBABILITIES → SOME GATES CHANGE PHASE ONLY → A ROTATION HAS AN ANGLE → ORDER CAN MATTER
The learner should understand that a gate does not read the state: it moves it, and the move can always be undone.
The key conceptual transition is:
“A gate does not read the state. It moves it, and the move can always be undone. On the sphere, every gate here is a rotation.”
This section should prepare the learner for Multi-Qubit Systems (02.05).
________________________________________
Learning Outcomes
By the end of the section, the learner should be able to:
	Describe a gate as a reversible operation that moves a state to another point, not a measurement and not a way of reading the state.
	Predict the outcome probabilities after I, X, Z, and H, starting from the named states.
	Explain that Z changes phase without changing the immediate Z-basis probabilities.
	Describe X, Y, and Z as half turns about the x, y, and z axes, and H as a half turn about the axis halfway between x and z.
	Describe a rotation gate as a rotation by an angle about an axis, where the angle sets the result.
	Show that H can turn a phase difference into a probability difference: |+⟩ and |−⟩ look the same before H and different after it.
	Show that the order of two gates can change the result, and recognize pairs where it does not.
	Explain that a gate can be undone by its inverse, and that a measurement cannot be undone this way.
	Read a gate table and the circuit symbols for I, X, Y, Z, H, and a rotation.
	Ask what changes when there is more than one qubit.

Page Structure
1. From Picture to Motion
Begin directly from the Bloch Sphere page.
Revisit the familiar progression:
A STATE IS A POINT ON A SPHERE
↓
A POINT CAN SIT ANYWHERE, BUT WE DO NOT YET KNOW HOW TO MOVE IT
Then ask:
“How can we move a state from one point to another?”
Name Module 01's “Apply mix (H)” button and say that it was the first gate. This page treats gates properly.
Do not rebuild the double-mix demo.
The learner should see a gate as the operation that moves a point rather than as a new kind of object.

2. What a Gate Is
Introduce a gate as a reversible operation that moves a state to another point.
Clearly distinguish:
	Gate — an operation.
	State — what it acts on.
	Outcome — what a measurement shows.
Do not imply that a gate is a measurement or reads the state.
Show a gate table for I, X, Y, Z, and H. For each gate give:
	Its circuit symbol, drawn through QedCircuit.
	What it does, in words.
	Where it sends each of the six named states, generated from QedGates and QedQubit.PRESETS.
Describe X, Y, and Z as half turns about the x, y, and z axes, and H as a half turn about the axis halfway between x and z.
Say that every gate here can be undone.
Include a short explanation such as:
“Is a gate a measurement?”
“No. A gate moves a state and can be undone. A measurement gives 0 or 1, and no later gate undoes it.”

3. Main Interactive — “Gate Explorer”
Make this the primary V1 interaction.
Allow the learner to choose a start state, add gates, and watch the point move.
At minimum support:
	Preset buttons for the six named states, taken from QedQubit.PRESETS. Start with |0⟩.
	Gate buttons for I, X, Y, Z, and H.
	A rotation gate with an axis choice (x, y, or z) and an angle from 0° to 360°, as a slider with a typed value.
	An “Apply” action that appends the chosen gate to a chain of up to four gates.
	“Undo with the inverse gate” and “Remove the last gate”.
	Resetting the view to its starting state.
When the learner applies a gate:
	Sweep the point along its rotation arc over about half a second. The final state is exact. The text readouts update immediately. Turn the sweep off when prefers-reduced-motion is set.
	Show the start as a pinned ghost and the result as the live point on the sphere, with the named points, the axes, and the projection from 02.03.
	Show the chain as a readable line, for example “|+⟩ → Z → |−⟩ → H → |1⟩”, and as a one-wire circuit through QedCircuit.
	Show the state description of the result, as on 02.03: two magnitudes and a phase angle at Beginner.
	Show the probability bars for the start and for the result, each with percentages.
	Show a one-line caption in words, such as “Z moved the point from |+⟩ to |−⟩. Height did not change, so the probabilities did not change.”
	Show the sphere, the chain, the description, and the bars in separate places.
When the chain has two or more gates:
	Show a panel for the opposite order, with the whole chain reversed, its own sphere and bars, and a sentence giving the verdict: same point or different points, same probabilities or different.
	Be honest about pairs where the order does not change the point. Never say that order always matters.
When the learner chooses “Undo with the inverse gate”:
	Append the inverse of the last gate: the same gate again for I, X, Y, Z, and H, and the negative angle for a rotation. Show the point return to where it began.
The learner should visually experience:
CHOOSE A GATE
↓
SEE THE POINT MOVE
↓
SEE WHAT THE PROBABILITIES BECOME
Reinforce the distinction established in 02.03:
A point is a state, never a measurement result.
Make the interaction resettable and allow learners to experiment with every start state, every gate, and every angle.
At Intermediate and above, as a level-aware behavior gated through QedLevel:
	Add S and T buttons.
	Add a matrix panel with the gate's matrix, the input column, and the output column.
	Show the written form of the result, as the raw result of the multiplication, with a note that a shared overall phase may appear and that the sphere ignores it.
The Beginner behavior must never depend on the level.
Make the interaction keyboard operable. Give each canvas role="img" and an aria-label that updates through QedBloch.formatText. Give the same information in the gate table and a text description of the chain. Summarize each step in an aria-live region.
The buttons and sliders are the non-3D alternative. Do not require dragging on a canvas.
Do not add two-qubit gates, measurement or shots, a circuit builder, or hardware here.

4. Z and the Hidden Phase
Reconnect to 02.03: moving around the equator changes the state but not the height.
Apply Z to |+⟩. The point moves to |−⟩ and the Z-basis probabilities do not change.
The learner should understand:
Z CHANGES THE STATE
↓
THE HEIGHT AND THE PROBABILITIES STAY THE SAME
Then apply H to |+⟩ and to |−⟩ and show the bars side by side: certain 0 against certain 1.
The learner should discover that H turns a phase difference into a probability difference.
Answer in one sentence the question left open on 02.01 to 02.03: this is how |+⟩ and |−⟩ are told apart. The measured version, with shots, is on a later page.
Include a prediction check with immediate explanatory feedback: a qubit is in |+⟩ and Z is applied; predict the Z-basis probabilities (50% and 50%), then compare with the bars. The feedback notes that the state changed to |−⟩.
Do not show shots or sampling here.
Do not describe phase as invisible for good.

5. Rotation Gates
Introduce the rotation gate as a half turn generalized: choose an axis and an angle.
Introduce the term:
Rotation gate — turns the point by a chosen angle about the x, y, or z axis.
Show that X, Y, and Z are the 180° cases.
State the direction once: the turn is by the angle about the positive end of the axis, counterclockwise when viewed from that end toward the centre.
The learner should understand:
RZ MOVES THE POINT AROUND THE EQUATOR
RX AND RY CHANGE ITS HEIGHT
↓
THE ANGLE SETS THE RESULT
Connect this directly to 02.03: RZ is the phase angle as an operation.
Include a transfer check with immediate explanatory feedback: use a rotation to make |0⟩ give outcome 1 about 25% of the time. RY or RX at 60° works. The feedback notes that RZ cannot, because it never changes the height of |0⟩.
Do not give the probability formula at Beginner.
Do not teach hardware pulses or native gates.

6. Order Matters, Sometimes
Use the explorer to compose two gates and compare both orders.
Work one example: start at |+⟩. H then Z ends at |0⟩. Z then H ends at |1⟩.
Show a pair where the order does not change the point: X and Z in either order give the same point, the same move as Y, differing only by a global phase that the sphere does not show.
Say that gates are applied left to right in a circuit.
The learner should understand:
THE SAME TWO GATES
↓
A DIFFERENT ORDER CAN GIVE A DIFFERENT POINT
Include a conceptual check with immediate explanatory feedback that explains every wrong choice: starting from |+⟩, which gates change the Z-basis probabilities? Only H does. I does nothing, X leaves |+⟩ where it is, and Z moves it to |−⟩ at the same height.
Do not imply that order always matters.
Do not teach matrices or circuits as a topic yet.

7. Beyond the Core
Build the heading inside the Intermediate block, as on 02.01 to 02.03, so a Beginner sees neither an empty heading nor a table-of-contents entry for it.
[Intermediate] Gates as Matrices
Add a gated block that covers:
	I, X, Y, Z, and H as 2×2 matrices, with H normalized by 1/√2.
	Matrix–vector multiplication, shown on the explorer's before and after.
	Y with its imaginary entries.
	HZH = X as a worked check.
[Intermediate] Rotations, S and T, and Inverses
Add a second gated block after the first, covering:
	RX, RY, and RZ with the half angle, and P(1) = sin²(θ/2) for RY on |0⟩.
	S and T as quarter and eighth turns about z.
	Composition as matrix multiplication, with the reading-order warning: circuits read left to right and matrix products right to left. State both conventions side by side.
	Inverse gates, including the negative angle for a rotation.
	The global-phase caveat: X and RX(180°) differ by a global factor that the sphere cannot show.
Explain the ideas visually, through the explorer's matrix panel, rather than relying on the equations.
Do not teach two-qubit matrices. Tensor products belong to 02.05.
Do not argue unitarity here. The Advanced block only names it.
[Advanced] Naming the Formalism
Add a very short gated block naming unitarity, universality, and gate decompositions, with no formalism.
Build all three as gated blocks as described in @llm/CONVENTIONS.md section 7.

8. From One Qubit to Two
End by comparing what the learner can do now with what is still unknown.
So far:
MOVE ONE QUBIT'S STATE ANYWHERE
↓
PREDICT WHERE IT LANDS
↓
UNDO THE MOVE
versus:
USE MORE THAN ONE QUBIT
↓
WRITE THEIR OUTCOMES TOGETHER
↓
LINK THEM
Present a final example with two qubits that each have their own state, side by side, without any two-qubit gate.
Ask:
“What changes when there is more than one qubit?”
Then introduce the next problem:
One qubit's state is now something we can move and undo. We have not yet said what a second qubit adds.
Do not mention CNOT, a two-qubit table, or entanglement by name here.
End with:
“What changes when there is more than one qubit?”

Important Pedagogical Constraints
Do not imply:
A GATE = A MEASUREMENT
Instead teach:
A gate moves a state and can be undone. A measurement returns 0 or 1 and is not undone by a gate.
Do not imply:
ORDER ALWAYS MATTERS
Instead teach:
Some pairs give a different point in a different order, and some pairs, such as X and Z, give the same point.
Do not imply:
THE ROTATION ON THE SPHERE = A PHYSICAL ROTATION OF THE QUBIT
Instead teach:
The sphere is a picture of the effect on the state. How hardware does it belongs to Module 04.
Do not imply that Z does nothing. It changes the state and the phase, even though the Z-basis probabilities stay the same.
Do not imply that phase is invisible for good. After an H it shows up in the probabilities.
Do not imply that |+⟩ and |−⟩ were told apart by a measurement on this page. The page shows probabilities after H; measurement belongs to 02.07.
Do not imply that X, Y, Z, and H are the only gates, or that every gate is one of these.
Do not imply that a circuit is read right to left, or that a matrix product is read left to right. At Intermediate, state both conventions side by side.
Do not teach two-qubit gates, CNOT, entanglement, the circuit builder, shots and the Born rule, hardware pulses, native gate sets, or universality here.
Keep Beginner V1 focused on the mental model required to understand why more than one qubit changes the picture.

End State
The learner should leave with:
A GATE MOVES THE POINT
↓
HEIGHT SETS THE PROBABILITIES, AND Z CHANGES PHASE ONLY
↓
H MAKES PHASE VISIBLE, AND A ROTATION'S ANGLE SETS THE RESULT
↓
ORDER CAN MATTER, AND EVERY GATE CAN BE UNDONE
And understand the central relationship:
Gate → move of the point → new probabilities, with the phase carried along.
The central takeaway should be:
A gate is a reversible move of a state. On the sphere each gate here is a rotation: Z changes phase only, H turns a phase difference into a probability difference, a rotation's angle sets the result, and the order of gates can matter.

“What changes when there is more than one qubit?”
