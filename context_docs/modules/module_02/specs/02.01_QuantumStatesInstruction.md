This section opens Module 02 — Quantum Computing Fundamentals. Module 01 gave the qualitative picture. Module 02 develops its precise meaning, and this page starts by separating what a state is from what a measurement shows.
________________________________________
Goal
Teach the learner how a quantum state differs from a measurement outcome, building on the qualitative picture of qubits from Module 01.
The central progression is:
PREPARE A STATE → MEASURE IT → SEE ONE OUTCOME → REPEAT TO SEE A PATTERN → THE PATTERN COMES FROM THE STATE
The learner should understand that a state is what a preparation produces, and that an outcome is one result drawn from it.
The key conceptual transition is:
“A state is not what you see. It is what is prepared, and what you see is one outcome drawn from it.”
This section should prepare the learner for Qubit Representation (02.02).
________________________________________
Learning Outcomes
By the end of the section, the learner should be able to:
	Explain what it means to prepare a state, and why the same preparation gives the same state.
	Name the two basis states, |0⟩ and |1⟩, and say what outcome each gives when measured.
	Distinguish a state from a measurement outcome.
	Predict the pattern of outcomes for a prepared |0⟩, a prepared |1⟩, and a prepared balanced superposition.
	Explain that a single outcome of a balanced superposition looks random while many outcomes show a pattern.
	Explain that a superposition is not a classical bit whose value is merely unknown.
	Explain that counts from one kind of measurement cannot by themselves tell a superposition from classical uncertainty.
	Recognize that a state comes with numbers, called amplitudes, that decide the probabilities of the outcomes, and that a state can carry something beyond those probabilities, called phase.
	Ask how a state can be written down so that we can calculate what it will do.

Page Structure
1. From Bits to States
Begin directly from Module 01's qualitative picture of qubits and measurement.
Revisit the familiar progression:
A CLASSICAL BIT HAS A VALUE
↓
YOU READ THE VALUE
Then ask:
“For a qubit, is what it holds the same as what you see?”
Introduce the page's job: separating the two.
The learner should see a state as something more than a bit's value rather than as a bit with an unknown value.

2. Preparing a State
Introduce preparation as a recipe that sets up a qubit.
Clearly distinguish:
	State — what a preparation produces.
	Preparation — the recipe that produces it.
Introduce |0⟩ and |1⟩ as names for the two basis states. Introduce a third recipe that prepares a balanced superposition.
Show that the same recipe gives the same state every time.
Do not imply that the same preparation gives the same outcome every time.
Do not use the name |+⟩, gate names, or any notation beyond |0⟩ and |1⟩.
Include a short explanation such as:
“If you prepare a qubit the same way twice, do you get the same result twice?”
“You get the same state. What you see when you measure it can still differ.”

3. Main Interactive — “Prepare, Predict, Observe”
Make this the primary V1 interaction.
Allow the learner to choose a preparation, predict what repeated measurements will show, then run shots and see the result.
At minimum support:
	Choosing among a prepared |0⟩, a prepared |1⟩, and a prepared balanced superposition.
	A prediction step with three choices: always 0, always 1, or about half each.
	Running a chosen number of shots, for example 1, 10, or 100.
	Running again, with the series continuing from the last run.
	Resetting the view to its starting state.
When the learner runs shots:
	Show the results as counts and bars, with a visible “simulated” label.
	Show a single shot as one result, and many shots as a pattern.
	Give immediate feedback on the prediction, and for a wrong choice explain why it does not match the preparation.
	Show a one-line plain-language description of the prepared state, such as “always gives 0 when measured” or “gives 0 or 1 about equally often.”
	Show the preparation, the state description, and the observed outcomes in three separate places.
The learner should visually experience:
CHOOSE A PREPARATION
↓
PREDICT, THEN MEASURE
↓
SEE OUTCOMES AND A PATTERN
Reinforce the distinction established at the start of the page:
A state is what was prepared. An outcome is what one measurement returned.
Make the interaction resettable and allow learners to experiment with different preparations and shot counts.
Use the seeded, advancing sequence of shared QedShots so every page load starts with the same first run and each “run again” gives new results.
Do not compare sampled results with theoretical values here; 02.07 owns that.

4. State vs. Outcome
Make the distinction explicit.
State
What was prepared. A property of the preparation, not of any one measurement.
Outcome
What one measurement returned. Different outcomes can come from the same state.
Use the interactive's results to show that:
One outcome is not the state.
At Beginner level, show this with a short comparison of what each is, how you get it, and what one run versus many runs tells you.
Include two checks with immediate explanatory feedback, including why each distractor is wrong:
	A conceptual question: given short statements, mark each as describing a state or an outcome.
	A transfer task: a new preparation is described as “prepared the same way as the balanced one.” Ask what 100 shots should look like.

5. A Superposition Is Not a Hidden Bit
Contrast a classical coin hidden under a cup with a balanced superposition.
For the coin, the result already exists and is merely unknown. Do not claim that the quantum case is the same, and do not claim that this page's counts prove otherwise.
State plainly that counts from this one kind of measurement look the same for both, so counts alone cannot separate them.
Ask:
“If the counts look like a fair coin, how could a superposition be anything more?”
Point to the evidence in Module 01, by name and with links:
	The Superposition demo, where mixing a qubit twice returns a certain outcome and mixing a random bit twice leaves it 50/50.
	The CHSH game in the Entanglement section, where an entangled pair wins more often than any pre-arranged strategy can.
Say that later pages in this module, on gates and measurement, develop the first of these.
Do not teach interference or Bell tests here.
Do not imply any single interpretation of quantum mechanics, or a literal picture of “both 0 and 1 at the same time.”

6. The Numbers Behind the Probabilities
Introduce amplitudes in one short block.
Explain conceptually:
A state comes with numbers, called amplitudes, that decide the probabilities of the outcomes.
Mention phase as a second ingredient: a state can carry something that the outcome probabilities do not show. No demo and no calculation.
The learner should understand:
STATE
↓
NUMBERS THAT DECIDE THE PROBABILITIES
Do not require vectors, complex numbers, or any calculation at Beginner level.

7. Beyond the Core
[Intermediate] Same Counts, Different States
Add a short gated block.
Explain that two different states can give identical counts for this measurement, so the counts do not determine the state.
Use no formulas.
Preview 02.02 and 02.03 without teaching them.
[Advanced] Pure and Mixed States
Add a very short gated block.
Name the difference between a pure state and a mixed state, with no formalism.
Optionally cut this block if the page becomes heavy.
Build both as gated blocks as described in @llm/CONVENTIONS.md section 7.

8. From States to Writing Them Down
End by comparing what the learner can do now with what is still missing.
So far:
PREPARE A STATE
↓
MEASURE IT
↓
SEE AN OUTCOME
versus:
WRITE THE STATE DOWN
↓
CALCULATE WHAT IT WILL DO
↓
PREDICT THE OUTCOMES
Present a final example with the balanced superposition.
Ask:
“How can we write a state down so we can calculate what it will do?”
Then introduce the next problem:
We need a way to describe a state precisely enough to calculate with it.
Do not explain notation or calculation here.
End with:
“How can we write a state down so we can calculate what it will do?”

Important Pedagogical Constraints
Do not imply:
STATE = OUTCOME
Instead teach:
A state is what a preparation produced. An outcome is what one measurement returned.
Do not imply:
SUPERPOSITION = A HIDDEN CLASSICAL BIT
Instead teach:
Counts from this one kind of measurement look the same for a superposition and for classical uncertainty, so they cannot tell the two apart. Other evidence does.
Do not imply that these counts prove a superposition is more than classical uncertainty.
Do not imply that measurement reveals a value that already existed.
Do not imply that the same preparation gives the same outcome each time. It gives the same state and the same pattern of outcomes.
Do not imply that the simulated counts come from real hardware. They are simulated, ideal, and noiseless.
Do not teach vectors, complex numbers, the normalization equation, the Born rule as a formula, gates, the Bloch sphere, or measurement formalism here.
Keep Beginner V1 focused on the mental model required to understand why a state needs to be written down precisely.

End State
The learner should leave with:
A PREPARATION PRODUCES A STATE
↓
A MEASUREMENT RETURNS ONE OUTCOME
↓
MANY OUTCOMES SHOW A PATTERN
↓
THE PATTERN COMES FROM THE STATE
And understand the central relationship:
Preparation → state → outcome, with one outcome never the whole state.
The central takeaway should be:
A quantum state is what a preparation produces. What you see is an outcome drawn from it, and one kind of measurement does not show you the whole state.
End with:
“How can we write a state down so we can calculate what it will do?”
